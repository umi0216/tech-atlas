# ADR 0001：第四版空间前端

状态：已实施，2026-10-21。

## 问题与约束

在暂不接入数据库的阶段，交付可直接访问的跨学科三维界面，保留原版记录和静态部署方式。既要支持真实三维交互，也要覆盖未开放 WebGL 的运行环境；选型不以维护者熟悉的技术栈为前提。

## 选择

使用原生 ES 模块分离知识、持久化、界面和渲染，采用锁定版本的 Three.js 0.186.1 提供 WebGL 空间；esbuild 生成无需运行时安装的单一脚本。Three.js 选择依据为透视相机、可编程点云、球体材质、拾取和轨道控制在本轮原型中的实际表现。

当前界面状态与导航范围有限，暂未引入应用框架。未来内容编辑与服务端同步扩展时，重新评估状态管理和组件框架；渲染器及数据访问边界独立保留。此项决定不推导出长期固定的后端技术栈。

无 WebGL 时采用 Canvas 透视投影：真实三维点经旋转和投影生成屏幕位置，按深度绘制星体，并同步 DOM 标签。兼容视图保持相同层级导航、选择、旋转和缩放。它的绘制预算、光照与性能不同于 WebGL，不宣称完全相同的画质或承载量。

## 数据与迁移

公开知识、个人记录与空间对象分别存在；渲染对象不写入知识存储。新版技术记录通过适配器与原 localStorage 互通，新增记录使用独立键；完整导出包含两部分。原初始数据保留，尚未执行全量数据格式迁移。

## 验证与限制

Chromium 141 在软件 WebGL 环境实际创建 WebGL 渲染器；模拟关闭 WebGL 后实际进入 Canvas 兼容渲染。检查了层级导航、搜索、阅读、收藏、记录保存、技术数据互通、JSON 导出和手机布局。云浏览器检查了兼容视图的实际视觉与交互。

目前一次显示一层，初始内容整体随脚本提供，未实现大规模异步知识分块。新增区域多为方向索引；当前版本也未提供数据库同步、内容审阅或公共多人协作。GPU 与兼容渲染在真实设备上的性能还需要持续测量。
