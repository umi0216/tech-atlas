# 架构与演进路线

状态：设计基线。除“当前实现”外，以下均为拟建设能力，实施前按当次需求细化。项目愿景见 [PROJECT_VISION.md](PROJECT_VISION.md)。

## 当前实现

第四版新增跨学科入口：七个学科、可展开的数学与计算分支、知识阅读、全局搜索、目录、收藏和个人记录。使用 Three.js WebGL 三维渲染，并为无 WebGL 设备提供同样基于三维坐标、透视投影与旋转的 Canvas 兼容视图。当前知识集包含 108 个条目（含根节点），多数新增学科先提供方向索引，尚未建设完整内容库。

新代码拆分为 `src/knowledge.js`（公开结构）、`src/store.js`（浏览器记录）、`src/space.js` / `src/canvas-space.js`（空间视图）和 `src/universe.js`（界面与导航）。部署产物为 `build/universe.js`，根入口仍为 `index.html`。旧版 SVG 技术星图、里程碑与 JSON 备份保留在 `legacy.html`。

原有 50 个技能 ID 与 `tech-atlas-v2` 存储键保留，新技术记录通过适配器读写原格式；新知识的个人记录使用 `atlas-personal-v1`。新版备份包含两部分，旧版备份可导入。原始 `data.js` 暂时保留历史示例自评，后续再做完整的数据源迁移。当前没有数据库、账户服务或跨设备自动同步。

## 技术选型原则

依据维护者于 2026-10-21 补充的要求，技术适配项目需求优先，不以维护者熟悉某个语言、框架或既有 ERP 技术栈为选型前提。此前讨论中的 Vue / Spring Boot / PostgreSQL 组合仅为候选，未作最终决定。

先定义交互、数据正确性、内容生产、离线与同步、性能和部署要求，再比较候选。同等效果与质量下，优先采用更先进、持续维护且有长期演进能力的技术。前瞻性通过实际能力判断，包括渲染与计算效率、类型与数据约束、跨端与离线支持、标准兼容、工具链和可迁移性；不能只根据发布新旧判断。

选择通过小型原型和架构决策记录落实：记录问题、候选、实测环境、采用理由、代价与退出路径。运行时、框架、3D 引擎与数据库分别评估，不把某个整套技术栈当作不可拆的默认答案。

## 开发环境与生产环境

当前代理使用的云端开发工作区用于编辑、构建、测试和预览；不能假定它具备生产所需的长期在线、持久磁盘、固定入口、进程托管或服务承诺。代码进入 GitHub；工作区进程和本地路径不作为生产依赖。

已有 GitHub Pages 继续提供当前公开版本。未来后端需部署到明确的运行目标；维护者已有 Linux 服务器或电脑可作为候选，其可用性、网络、持久存储和访问方式在部署任务中实际核实。不得假设代理已接入这些设备。

交付方向是可重复的构建测试、版本化产物、配置与数据分离、自动部署及可回滚发布。根据运行目标选择容器或其他合适的部署格式，减少人工搬运与环境绑定。当前并未实现后端部署流水线；不能因这份规划宣称已连接生产服务器。

## 数据边界

| 实体 | 建议字段 | 约束 |
| --- | --- | --- |
| KnowledgeNode | id, kind, title, aliases, summary, contentRef, revision | id 稳定；坐标、颜色和掌握度不构成知识身份 |
| KnowledgeRelation | id, fromId, toId, type, explanation, sourceIds | 关系有方向和语义；引用存在；重复关系可检查 |
| Resource | id, kind, title, authors, locator, license, sourceRevision | 来源、授权与材料版本可追溯 |
| LearningPath | id, goal, entryCriteria, steps, assessments, revision | 顺序依据目标；可选分支与先修显式表达 |
| PersonalProgress | ownerId, nodeId, selfRating, state, priority, updatedAt | 与公共知识分离；未评价使用 null，保留自评属性 |
| LearningEvent | id, ownerId, nodeId, type, occurredAt, evidenceRefs | 记录练习、验证与修订，支持回看变化 |
| PersonalNote / Evidence | id, ownerId, nodeIds, bodyOrRef, visibility | 私有为默认设计方向；公开需要明确发布操作 |
| SpatialLayout | nodeId, scopeId, position, layoutVersion | 可重新计算和缓存，不修改知识关系 |

节点种类可以从 `discipline / branch / topic / concept` 起步，按内容需求扩展。允许一个概念在多个分类下被引用，保持同一个稳定 ID，避免复制后产生多个互相矛盾的版本。

关系至少区分 `contains`（分类包含）、`prerequisite`（先修）、`related`（相关）、`appliesTo`（应用于）、`supportedBy`（材料支持）。分类包含应检查环；一般知识关系允许环。某条学习路径选定的先修图需能解释并检查冲突，不能假定整个知识图谱是一棵树。

掌握状态、掌握深度与资料收录状态分别存储。旧版 mastery/status 的具体含义通过迁移适配保留，不静默重解释历史数据。内容格式、个人备份格式和接口各自有显式版本。

## 模块边界

1. **内容层**：知识条目、关系、资料索引和内容修订。
2. **应用层**：搜索、学习路径、个人记录、导入导出与未来同步。
3. **视图层**：3D 宇宙、二维地图、目录、条目阅读与档案编辑，共享选择和导航状态。
4. **持久化适配层**：先支持静态内容与浏览器存储，再按需求接入服务器；业务逻辑不直接依赖渲染对象或具体存储接口。

已开始分离数据、持久化与空间视图，后续继续完善接口与规模适配。渲染器消费视图模型，不直接写学习数据。现有 SVG 视图在迁移期继续承担功能回退与对照验证。

## 3D 空间的建设顺序

- 学科总览：建立真实的三维坐标、透视、近远层次与可拾取目标；当前技术地图作为其中一个入口。
- 连续导航：学科 → 分支 → 主题 → 概念；镜头目的地、返回路径和面包屑一致。旋转、平移和缩放有合理边界，可随时中断。
- 多尺度显示：远景聚合，近景逐层加载；标签按屏幕空间选择显示，关系按选择和缩放层级出现。
- 阅读衔接：选择概念打开清晰的二维阅读界面，公式、引用、相关节点与个人记录可达。
- 性能与适配：复用绘制资源，限制同时可见对象；根据实测调整像素密度和动效。暂停不可见场景，支持触摸、键盘和非 3D 回退。

不以背景粒子数量衡量知识规模。视觉距离可以表达导航层级或布局分组，若不代表学术距离或难度，应明确其含义。

3D 引擎与前端框架在原型阶段以可维护性、交互实现和设备实测作选择，锁定具体依赖版本后实施；此文不预先承诺某个库版本或性能结果。

## 分阶段交付与验收

| 阶段 | 交付 | 验收重点 |
| --- | --- | --- |
| A：可扩展知识底座 | 新数据格式、稳定 ID、内容与个人记录分离、旧数据适配、数学示例分支 | 现有 50 节点及个人修改可迁移、导出和恢复；增加学科无需修改固定坐标表；校验重复 ID、悬空关系和分类环 |
| B：3D 知识宇宙 | 三维总览、逐层进入、搜索定位、与条目联动、二维回退 | 从总览进入数学分支、打开概念并返回；当前技术星图可用；鼠标、触摸、键盘均有完整路径；实测加载与帧耗时 |
| C：学习与内容闭环 | 条目模板、公式、来源、目标路径、练习验收、个人学习事件 | 完成一条目标路线，保存证据并回看进度；新增知识不自动改变掌握度 |
| D：服务器与跨设备 | 身份、服务端存储、增量同步、附件、备份恢复、部署文档 | 两台设备修改可同步；冲突可解释和恢复；从备份恢复演练通过；个人笔记不进入公开数据 |
| E：开放知识维护 | 内容版本、编辑审阅、纠错、公开读取接口与批量导出 | 可定位来源与修订，审核后发布并能回滚；公共发布与个人记录保持独立 |

阶段 A 与 B 可交替推进，每次提交都保持可用。下一次功能迭代的优先切片：**可扩展分类 + 三维学科总览 + 数学向下展开 + 原有技术档案入口**。未完善的内容标明范围，不填充虚假的海量知识或个人进度。

## 服务器引入原则

需要跨设备同步和持久化时再建设服务端；需要附件时再接入对象存储；需要复杂搜索或图遍历时先用实际内容与查询做验证，再决定是否增加专用组件。

初期服务端优先考虑一个边界清楚、可独立部署和备份的应用，知识节点与有类型的关系先通过明确的数据模型表达。微服务、图数据库、搜索集群、向量检索和多机编排都需要实际需求或测量结果支撑。

未来部署交付应包括环境配置示例、数据库迁移、健康检查、日志、备份与恢复步骤，以及静态入口的兼容方案。服务器地址、账户、认证材料和生产发布目标在当次部署任务中确认；不根据“有 Linux 服务器”推测连接参数。

## 持续维护要求

保持已有技能 ID、备份兼容性和可恢复性。迁移先提供备份与明确的回退步骤，再切换写入路径。每次更新记录已实现能力、验证范围和剩余限制。

规模验证使用与内容相符的分层样本，分别测量首屏、搜索、进入分支、标签拥挤、内存与帧耗时；性能目标在确定测试设备后制定，不宣称未经测试的承载量。
